# Experience library and maintenance Skills: bounded implementation

Date: 2026-11-01. Status: implementation authorized by the user after review of the complete plan.

## Purpose and boundaries

Curate useful experience, provide separately maintained Skills for human-initiated batch maintenance, and expose factual experience-use records. Planner retains creative ownership and optional reading/notes. The one-shot Critic, frozen rubric, renderer and independent judge keep their established roles. No RSI, automatic proposer/adoption, scheduler, mandatory reasoning forms, live inference, GPU runs, independent scoring or simulated workflows are introduced.

Repository content is English. The pre-change code is commit `0f6a48ca9d008a208f46503943b217cff3c2b00c` on `codex/creative-loop-v1`. Preserve unrelated working files and historical records. Implement on a separate branch and verify GitHub synchronization.

## Scope and order

1. Review all 45 staged E1 cards and overlapping active static material. Give every card a disposition, evidence qualification and destination. Preserve original files and IDs.
2. Write four complete demonstrations: authored design conflicts; category versus instance identity; coherent visual scope; input as visual conditioning. Provide precise historical evidence and limits. These are drafts for content review, not established strategies.
3. Create three project-local maintenance Skills: experience analysis, use review, and curation. Share one writing standard. Maintenance is explicitly initiated work; it may produce no new entry.
4. Organize one operating manual and two optional professional manuals. Preserve meaning and the complete style library. Connect question/renderer navigation to an explicitly scoped, read-only curated library.
5. Extend existing reads/events/exact call inputs with experience provenance. Separate prepared/answered calls, visible summaries/full pages, explicit model references and retrospective interpretation. No additional Planner fields are required.
6. Supply a deterministic batch export over explicitly listed run directories. Include missing/failed/incomplete work, source links and version cohorts. Interpretation belongs to maintenance Skills. No automatic usefulness score or publication.
7. Inspect source, parse syntax/configuration, check provenance/counts/links and inspect historical exports. Add focused regression cases but keep their execution and simulated/model workflows deferred as previously requested. Synchronize code and documents to GitHub.

## Acceptance

All 45 IDs have a disposition. Demonstrations distinguish recorded judgments, explanatory hypotheses and prospective strategies, including counterexamples and confounding. No policy quota or old intent/ledger/Critic diagnosis instruction enters the new manuals. Browse/search/read/link expansion share the same catalog scope. Drafts and maintenance Skills remain unavailable to runtime knowledge access. Exact call visibility is not equated with attention/adoption. Historical missing data remains missing. Batch records retain all specified runs and do not mix incompatible scoring protocols or knowledge versions. No final scoring leaks into the current Planner. Current jobs and snapshots are unchanged.
