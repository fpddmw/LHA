# Wiki and evidence-driven proposer upgrade

Approved scope, 2026-10-31: save this plan, implement and locally verify the Wiki and proposer changes. No paid model calls, GPU work, benchmark replacement or automatic experience adoption. The seven Bernini fewshot loops require the user's subsequent review and authorization; their eventual objective is delivery of selected results, with bounded attempts rather than compulsory three-generation runs.

## Intended increment

Retain the existing design library and dynamic model-led reading. Add a small linked Wiki connecting contextual concepts, complete experimental cases, experience and original evidence. The initial authored material is human-assisted development knowledge, not an automatic RSI result or a validated policy.

Start with three judgment questions: scene identity versus stylization; rewording versus a changed visual realization; connected visual changes versus a presumed local repair. Preserve contested judgments and distinguish observations, interpretations and untested strategies. No fixed reasoning sequence, new Planner forms, aesthetic template or mandatory stopping rule.

## Implementation

1. Add readable concept/case pages and explicit links to existing design material. Extend the existing knowledge catalog, snapshots and read tools to resolve stable Wiki links and verified reference images. Reuse the experience version/publication mechanism for concept revisions; historical case evidence remains immutable.
2. Let the proposer read linked knowledge and inspect recorded development frames. Bind every image to a run, video, timestamp and hash. Let it propose concept or experience revisions, or return no change with a useful evidence request. Keep a three-change budget and freeze the underlying cases, operational manuals, Critic and scoring definitions.
3. Feed actual paired replay outcomes, returned reading traces and decisions into the next proposal. Use a bounded, resumable revision series against the same original base. Stop on a behavioral pass, no useful change, missing judgment evidence, or budget. A pass requests live validation; it never publishes knowledge or claims video improvement.
4. Verify reference delivery in replay, data/version isolation, real archived case links, proposal caching, immutable evidence, bounded revision and unchanged legacy interfaces with local tests and scripted models. Save concrete model-visible examples and a review receipt.

## Next stage after review

Run the seven accepted fewshot tasks on Bernini through the full loop toward a selected deliverable. Record first/selected candidates, prompts, reads, predictions, Critic feedback, actual costs and unfinished requirements. This is prototype development; exposed examples remain development material. Rebuild the wider benchmark separately around meaningful everyday-to-artistic transformations. Independent validation and Claude calibration remain separate prerequisites for efficacy claims.

## Implemented interfaces

- The shared catalog now includes the authorized human-assisted starting Wiki: three concepts, four immutable experimental cases and one map. This changes the starting library for future runs; old E0/E1 snapshots and completed replays remain unchanged. It is not automatic promotion of E1 or a model-generated proposal.
- Stable `[[id|reading reason]]` links resolve in normal `read` results. Planner can open up to four indexed reference images together. Replay now actually attaches those references to the next model request, with historical-reference labels distinct from task observations.
- The proposer receives compact topic summaries, development statistics and replay decisions. It can read knowledge, search, inspect recorded source/candidate frames, and page through complete prior replay traces. Cases and their assets are hashed; the model can revise concepts or experience, not historical outcomes or operating/evaluation definitions.
- `round` accepts `max_revisions` (default 2, maximum 3) and optional sealed `feedback_packets`. Each proposal is compared with the same original base and has the same three-card change limit. A missed behavior target feeds actual reads/decisions back; an incomplete judgment stops for review. No change can carry an evidence request. Successful behavior stops at `ready_for_validation`, without rendering or publication.
- `replay-feedback --replay <result.json> --output <packet.json>` packages an existing replay without calls. `propose --feedback <packet.json> ... --execute` can use it in a subsequently authorized model run. Recorded calls and completed proposal versions resume without dispatching duplicates.

Review artifacts are under `out/wiki_proposer/20261031/`: a local linked report, exact model-visible packets, packaged feedback from the four real historical replay points, a scripted interface demonstration, and software-test receipts. The demonstration uses real archived evidence with scripted responses; it measures data delivery and recovery, not intelligence or improved video quality.

## Evidence and limits

The preceding 24 real replay samples used E0 and human-assisted E1 at four exposed decision points. Inputs and stopping decisions did not differ; no rendering occurred. This upgrade supplies learning mechanisms and grounded reading material. Its quality benefit requires real model use and generation after review. Existing assisted E1, old replay outputs and historical evaluation records remain unchanged.
