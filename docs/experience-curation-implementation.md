## Recording and maintenance interface

[Interface documentation](experience-usage-interface.md) describes the passive call receipt, per-run projection, catalog contract and explicit batch command. The final saved model input is the provenance anchor, after context fitting. Catalog exposure, search snippets, text pages and attached reference images are distinguished. Response/dispatch status is separate from visibility; neither establishes adoption.

The exporter retains literal model references with their actual wording. It does not decide whether a phrase means adoption or rejection, reconstruct private reasoning, or award causal credit. Unresolvable archived text remains an explicit coverage gap. Maintenance Skills can interpret the exact events and record their own judgments separately.

The batch exporter reads only listed development runs, retains missing/incomplete/failed records, rejects duplicate source directories and keeps output separate from input. It has no renderer or model dependency. Results remain separated by source snapshot and evaluation protocol. Known generation time is counted for recorded generated candidates; failed-job and LLM costs remain outside that total.
