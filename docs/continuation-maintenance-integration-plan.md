# Connect continuation decisions to experience maintenance

Date: 2026-11-01. Authorization: the user approved this review and its bounded repairs, offline verification, commit and GitHub synchronization. Live experiments, model calls, GPU work and polling remain paused.

## Review findings and intended result

The continuation runtime records explanations, but the maintenance consumer was not updated with it. A useful explanation must be traceable to the knowledge and evidence available before the decision, the actual input and prompt, and the later outcome. Maintenance Skills interpret that relationship and improve conditional guidance. Runtime accepts nonempty explanations without evaluating their quality.

Confirmed gaps:

- Experience-reference extraction ignores `generate.justification`.
- The maintenance projection lacks joined continuation decisions, delivery proposal/confirmation stages and policy/migration identities. Raw explanations survive in action arguments, but require manual reconstruction.
- The three maintenance Skills and shared standard do not explain how to use this material. Professional revision guidance does not connect a prior explanation to the returned result.
- Completed independent judgments and the Direct baseline live in separate topic archives. Explicit offline maintenance access and portable evidence navigation are needed.
- All fourteen active approved entries still carry a draft label. Some maintenance references point to the historical staged package as the current library.
- After an ordinary Critic returns an invalid answer, satisfied `finish` can create a second scoring request. Delivery must reuse or reconcile the original request rather than bypass the one-shot boundary.

## Maintenance responsibilities

- Analysis explains why the stated judgment and actual intervention succeeded or failed, and develops a useful condition/preference.
- Use review examines discovery, interpretation, application and rejection of a specific saved experience version, including literal references in explanations and implicit use assessed by the maintainer.
- Curation revises entries, summaries, navigation or professional guidance where the diagnosis belongs, retaining evidence and replacement history.

These capabilities remain separately usable. A batch ends with an authorized maintenance pass and reviewable edits, not automatic adoption. Critic retains its frozen scoring role. Full/none share operating guidance; only full exposes empirical experience. Style content and renderer/model conditions remain unchanged.

## Implemented changes and verification

### One connected maintenance record

`experience_usage.py` now exports `experience-use-v2` and `experience-batch-v2`. It joins the exact saved question/notice and explanation to the dispatched input/prompt, returned candidate, online report, and proposed/confirmed delivery. It records literal experience references inside `generate.justification` alongside the actual call-level source exposure. The reading page links candidate videos and reports; the complete JSON retains observed frames and all attributed findings.

Copied run artifacts resolve within the retrieved run while retaining their original paths. An explicitly supplied completed development topic archive adds hash-checked Direct/first/final judgments, kept separately by judge. If that archive is unusable, its error stays visible and the run's decision material remains available. Default runtime reporting never reads independent judgments.

### Guidance now uses the record

Previously, the maintenance Skills discussed prompts, choices and outcomes generally, while the new continuation explanation existed only in raw operations. They now inspect the distinction stated before an attempt, whether the actual intervention implements it, and what its outcome changes in that account.

- Analysis: “A declared change of realization may still preserve the same visual operation; explain which relationship remained unchanged and what construction would address the conflict.”
- Use review: “If explanations repeat ‘a different approach’ while retaining the failed construction, sharpen the account's discriminator and show what a changed construction would look like.”
- Curation: “A changed understanding of a renderer belongs in an experience entry; a reusable way to interpret results belongs in a professional manual; argument names, report reuse and delivery confirmation belong in the operating manual.”

The shared writing standard, professional manuals, reading guides and both full/none operating manuals carry the corresponding responsibilities. Planner can use existing history and optional notes to reconsider a prior explanation. No new form, answer scoring, automatic content update or scheduling component was introduced.

The fourteen approved entries now carry consistent approval labels and refreshed catalog versions/hashes. Their empirical bodies are unchanged. Historical staged materials and frozen run snapshots remain intact.

### One-shot Critic repair

Previously, a rejected ordinary report could cause `finish` to request a second scoring interpretation. A valid existing report is now reused; an existing unresolved or invalid request retains its original artifacts and pauses for reconciliation. Only a candidate without any prior request receives a new report. Transport recovery retains the original request identity.
