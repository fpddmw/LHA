# Express an edit for its actual input

[Experience map](README.md) · [Design expression](../guides/design-expression.md) · [Bernini evidence](../model-experience/bernini-r.md)

Version 1. The input-aware recommendations are common-sense starting guidance. The Bernini observations below are scoped experimental evidence. No universal prompt length, sentence order or semantic-preservation recipe is established.

## Write for what the generator receives

When generating from the original, describe the selected target coherently enough to realize the requested transformation. When continuing a candidate, describe the change relative to that actual candidate. A focused instruction is often a useful starting choice when most of the appearance is already achieved. A complete target description may be useful when several connected parts must change together. Choose the form for the task rather than a mandatory full/incremental label.

The renderer does not inherit the Planner's notes, earlier critique or unprovided reference videos. Words such as "fix that" or "restore the original" can leave the desired result unspecified. Describe the relevant wanted state when the renderer cannot see the comparison available to the Planner.

## Keep detail relevant to the current design

A precise local request generally benefits from expression centered on the requested change and its dependencies. An open style request can benefit from developing a specific interpretation through visible relationships. Length alone does not determine which task needs more design work. Avoid expanding a narrow request simply to demonstrate creativity or use every available piece of knowledge.

Bind an important attribute to the intended object or part. A luminous tabletop rim and illuminated table supports are distinct targets. Explain a material relationship when it defines the design: pencil showing through transparent pigment conveys more than an unrelated list of materials. A clearer instruction still needs output inspection.

If a prompt is too large for the actual renderer, return to the design and choose which information matters. The runtime reports known limits; it does not silently cut text or append a universal template.

## What the Bernini probe actually supports

On the recorded 041 task, the short storybook request remained largely photographic, while versions with concrete pencil-and-watercolor features produced a clear illustration. This supports trying a visible elaboration of the selected medium for that model and task. The short etching request on 027 also worked, so elaboration is not uniformly necessary. Length and information content changed together.

The table-tennis outputs put blue glow mainly on lower supports despite a requested edge effect. Clearer part binding is a plausible wording improvement, not a demonstrated repair. Additional preservation clauses had inconsistent effects. Do not treat stronger wording as proven protection of structure or motion.
