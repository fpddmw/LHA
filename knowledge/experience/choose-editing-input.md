# Choose an editing input

[Experience map](README.md) · [Express an edit](express-edits.md) · [Inspect results](inspect-and-compare.md)

Version 1. Origin: initial common-sense guidance approved for use as a starting point. The route preferences below have not been established by a controlled multi-round comparison. Model-specific evidence can change them.

## Build on a result that already does the useful work

When a candidate realizes most of the requested appearance and the remaining change is localized and describable, prefer trying the change on that candidate. Its achieved materials, layout and style become the input rather than something the generator must reproduce from a description. Select the candidate for this particular change; the latest video or the strongest overall candidate need not be the best editing input.

Treat locality as an intention to test. A whole-video editor may change other regions despite a local instruction. If relevant experience or the current result shows this behavior, consider another candidate or the original. A focused instruction is not a pixel mask or a guarantee that other regions stay fixed.

## Recover a useful starting point when essential information is lost

If a candidate has substantially changed a key person, object, action or relationship, prefer an input that still contains the needed information, often the original. Repeated editing of a damaged representation can require the generator to invent missing structure. The original makes that structure available again, while the desired appearance must be generated anew.

A small remaining shape error does not automatically justify discarding a successful transformation. Inspect enough of the relevant area to judge the extent of the problem. When an older candidate already contains both the needed information and useful styling, it may be a better starting point than either the original or the latest result.

## Start a substantially different direction from a suitable source

When changing the overall design direction, prefer the original if the existing result strongly embodies an incompatible earlier direction. Continue a candidate when the new idea intentionally builds on its appearance. A branch is simply another generated result with its own input and prompt; there is no obligation to settle on one direction early.

## Use another sample when it can answer a real uncertainty

When the intended edit and instruction remain credible and one failure has no clear systematic explanation, another generation with the same input and prompt can help reveal whether the behavior repeats. Keep other settings comparable when that is the question. Such a sample consumes resources and does not itself repair an unclear instruction.

Repeated similar failures are a reason to reconsider the interpretation, expression, input or model capability. Merely replacing adjectives or adding stronger demands may repeat the same attempt without changing what the generator can do.

## Revisit earlier results and stop when appropriate

If continued editing adds unrelated changes, return to a less damaged version and reconsider the next change. Preserve useful alternatives. Different candidates may be suitable for different next steps or final delivery; a single mandatory incumbent is unnecessary.

Continue when a further action has a plausible benefit for the actual request or can resolve consequential uncertainty. Finish when the available result is suitable, when further attempts have little expected value, or when resources end. A resource stop can leave an incomplete task; describe that outcome accurately.

## Evidence available now

The [October 29 Bernini record](../model-experience/bernini-r.md) reports independent prompt conditions, not multi-round route comparisons. Its observed misplaced tabletop glow motivates inspecting the intended part, but does not establish that editing the generated video or restarting from the original is better. Subsequent route cases should retain input ancestry, prompts, settings, outcomes, evaluation conditions and counterexamples so these starting preferences can improve.
